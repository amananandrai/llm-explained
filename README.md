# LLM Explained

**Live site: https://llm-explained-lovat.vercel.app/**

A scroll-driven, interactive course on how large language models work, built from `plan/build-plan.md`.

## What is here

- **All 43 pages interactive:** Modules 0–41 plus the Module 0 KL sub-page. Each page follows the plan's template: hook, scroll-driven hero animation with play/step/scrub controls and a text transcript, the Intuition / Mechanics / Maths depth switch, colour-linked KaTeX maths, widgets, "what this picture leaves out", a 3-question quiz and further reading.
- **Architecture atlas (`#arch`):** the transformer drawn block by block in three eras (2017 encoder–decoder, GPT-style decoder, modern open-model block), then one diagram per open-weight model (Llama, Mistral, Mixtral, Qwen, DeepSeek, Kimi K2, Gemma, Phi, gpt-oss) generated from its configuration, plus a concept-by-model matrix. Every block links to the module that teaches it. The same widgets appear in Modules 6 and 16.
- **Navigation:** the top bar has two destinations (Curriculum, Architectures), a Modules menu listing every module by part with the current one marked, and one forward button (Start, Resume or Next module). Each page has an “On this page” row that jumps to its sections. The home page opens with four starting points before the full curriculum.
- **Plan-driven data:** `scripts/build_data.py` parses the build plan into `assets/data.js` (curriculum, tables, reading lists). If a module script fails to load, the page falls back to an outline generated from the plan.

## Run locally

```bash
./scripts/dev.sh                    # wraps index.html into dev.html
python3 -m http.server 8765         # then open http://localhost:8765/dev.html
```

Edit the plan and regenerate the data with `python3 scripts/build_data.py`. Paper links live in
`plan/paper-links.json` (keyed by the reference text in the plan); the script warns about any reference without a link.

## Layout

```
index.html              page shell (no build step)
assets/style.css        design tokens (light + dark), layout, components
assets/core.js          component library: router, depth switch, ScrollyStage, sliders, ProbabilityBars,
                        MatrixGrid, line charts, Quiz, MathBlock (colour-linked KaTeX), outline renderer
assets/kit.js           PipelineFlow/BlockDiagram, AgentTrace, tables, bar rows, checklists (Parts 3–7)
assets/arch.js          architecture diagrams: model configs (MODELS), parameter and KV-cache counters, stack renderer,
                        transformerDiagram / modelDiagram / conceptMatrix and the atlas page
assets/pycell.js        TryItCell: editable Python (Pyodide + NumPy) with a small `viz` charting module
assets/py/cells-*.js    one runnable Python cell per module (a: Modules 0–9, b: 10–20, c: 21–41)
assets/data.js          generated from the plan
assets/m/m<id>.js       one file per interactive module, lazy-loaded on navigation
assets/katex/           vendored KaTeX 0.16.11
```

## Deviations from the plan

- Plain JS + static files instead of Astro + MDX + React, so it runs with no build step. The component split
  matches the plan's library, so porting to Astro islands later is mechanical.
- Python cells load Pyodide 0.26 from the jsDelivr CDN on first Run; hosts that block the CDN (such as embedded previews)
  show a link to the live site instead.
- No real-model tokenizers, recorded agent traces or live LLM calls yet. Widgets that would need them
  use in-browser computation (byte-level BPE, a real HNSW, numerical KL, closed-form RLHF optimum, a tiny real
  transformer block in the capstone) or written examples and illustrative numbers, labelled on the page.
- Model configs (`MODELS` in `assets/arch.js`) are transcribed rather than generated by script. Each entry is marked `ver: 'config'`
  (checked against the vendor's config or model card, November 2026) or `ver: 'count'` (dimensions confirmed by reproducing the
  published parameter count). All 14 reproduce their published size to within 0.3%, except Kimi K2 (published as a rounded 1T).
  To add a model, add one entry; the diagram, spec card, diff and matrix pick it up.

## Deploy

The site is static. `scripts/build.sh` wraps the `index.html` fragment into a full HTML document and copies
`assets/` into `dist/`. `vercel.json` tells Vercel to run that script and serve `dist/`.

- **Vercel dashboard:** New Project → import `amananandrai/llm-explained` → Deploy (settings are read from `vercel.json`).
- **Vercel CLI:** `npx vercel --prod` from the repo root.
- **Any static host:** run `bash scripts/build.sh` and upload `dist/`.
